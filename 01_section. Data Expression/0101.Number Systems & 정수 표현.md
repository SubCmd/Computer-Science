## 1. 개념 및 정의

### 1-1. 왜 2진법인가?

컴퓨터의 물리적 본질은 **전기 스위치**
켜짐/꺼짐, 전압 높음/낮음 - 즉 상태가 둘 뿐임.
자연스럽게 **2진법(binary)**를 사용함.

| 용어 | 정의 |
| ---- | ---- |
| **비트 (bit)** | binary digit. 0 또는 1, 정보의 최소 단위 |
| **바이트 (byte)** | 8비트 묶음. `2^8 = 256`가지 값 표현 |
| **진법 (base/radix)** | 한 자리에서 쓸 수 있는 기호의 개수. 10진법=0~9, 2진법=0~1, 16진법=0~F |


### 1-2. 자리값(positional notation)의 원리

모든 진법은 자리값으로 동작함. 10진수 `253`이 사실은:

```
253 = 2×10² + 5×10¹ + 3×10⁰ = 200 + 50 + 3
```

2진수도 정확히 같은 원리, 밑(base)만 2:
 
```
1101₂ = 1×2³ + 1×2² + 0×2¹ + 1×2⁰ = 8 + 4 + 0 + 1 = 13₁₀
```


### 1.3 주요 진법 비교표
 
| 10진수 | 2진수 (binary) | 8진수 (octal) | 16진수 (hex) |
|---|---|---|---|
| 0 | 0000 | 0 | 0 |
| 5 | 0101 | 5 | 5 |
| 10 | 1010 | 12 | A |
| 15 | 1111 | 17 | F |
| 16 | 10000 | 20 | 10 |
| 255 | 11111111 | 377 | FF |
 
> **16진법이 사랑받는 이유**: 16 = 2⁴이라서, **2진수 4자리 = 16진수 1자리**로 딱 떨어진다. 그래서 색상코드(`#FF5733`), 메모리 주소, UTF-8 바이트(Phase 1-2)를 16진수로 쓴다. 11111111을 쓰느니 FF가 훨씬 읽기 쉽다.
 

### 1.4 음수는 어떻게? — 2의 보수(Two's Complement)
 
비트에는 마이너스 기호가 없다. 그래서 음수를 표현하는 약속이 필요하다. 현대 컴퓨터의 표준은 **2의 보수**다.
 
**2의 보수 만드는 법** (예: 8비트에서 -5 만들기)
1. 5의 2진수: `0000 0101`
2. 모든 비트 반전(1의 보수): `1111 1010`
3. 1 더하기: `1111 1011` ← 이것이 -5
| 방식 | 0의 표현 | 장점 | 단점 |
|---|---|---|---|
| 부호-크기 | +0, -0 둘 다 존재 | 직관적 | 0이 둘, 덧셈 회로 복잡 |
| 1의 보수 | +0, -0 둘 다 존재 | 반전만 하면 됨 | 0이 둘 |
| **2의 보수** | **0 하나뿐** | **덧셈만으로 뺄셈 처리, 회로 단순** | 사람이 읽기 약간 불편 |
 
> **2의 보수의 마법**: 뺄셈을 별도 회로 없이 "음수를 더하는 덧셈"으로 처리할 수 있다. `7 - 5 = 7 + (-5)`. 이 덕분에 CPU(Phase 2)의 ALU가 훨씬 단순해진다.
 
**n비트 2의 보수 표현 범위**: `-2^(n-1)` ~ `2^(n-1) - 1`
- 8비트: -128 ~ 127
- 32비트: -2,147,483,648 ~ 2,147,483,647 ← SQL `INT`의 정체!
- 64비트: 약 ±9.2 × 10¹⁸ ← SQL `BIGINT`


### 1.5 오버플로(Overflow)
 
표현 범위를 넘으면 값이 "한 바퀴 돌아" 엉뚱한 값이 된다.
 
```
8비트 부호 있는 정수에서:
  127 + 1 = ?
  0111 1111 + 0000 0001 = 1000 0000 = -128 (!!)
```
 
> 실무에서 INT 컬럼이 21억을 넘어 음수로 뒤집히는 사고, 비트 시프트 연산 버그가 전부 이 원리. 그래서 큰 ID 컬럼은 `BIGINT`를 쓴다.

## 2. 예시

### 예시 1: 진법 변환을 Python으로 확인

```python
# 10진수 → 각 진법 (접두사 0b/0o/0x 주의)
n = 253
print(bin(n))   # 0b11111101   (2진수)
print(oct(n))   # 0o375        (8진수)
print(hex(n))   # 0xfd         (16진수)
 
# 문자열(특정 진법) → 10진수: int(문자열, 밑)
print(int("11111101", 2))  # 253
print(int("fd", 16))       # 253
print(int("375", 8))       # 253
 
# 자리값 원리를 직접 구현해보기 (2진수 → 10진수)
bits = "1101"
value = 0
for i, b in enumerate(reversed(bits)):   # 오른쪽(2⁰)부터
    value += int(b) * (2 ** i)
print(value)  # 13
```


### 예시 2: 2의 보수와 오버플로를 눈으로 보기

```python
# Python의 int는 무한 정밀도라 오버플로가 안 난다.
# 그래서 8비트 동작을 일부러 흉내내보자.
def to_int8(n):
    n = n & 0xFF              # 하위 8비트만 남김 (마스킹)
    if n >= 128:             # 최상위 비트가 1이면 음수
        n -= 256
    return n
 
print(to_int8(127 + 1))   # -128  ← 오버플로!
print(to_int8(-5))        # -5
print(bin(-5 & 0xFF))     # 0b11111011  ← -5의 8비트 2의 보수 표현
 
# numpy는 실제 고정 비트라 오버플로가 그대로 재현된다 (데이터 분석 시 주의!)
import numpy as np
x = np.int8(127)
print(x + np.int8(1))     # -128  (RuntimeWarning과 함께)
```

> **분석가에게 직결되는 함정**
> pandas/numpy에서 `int8`, `int16` 같은 작은 dtype으로 메모리를 아끼다가, 합계나 누적값이 범위를 넘어 음수로 뒤집히는 경우가 있다.
> 대용량 집계 시 dtype 확인은 필수

## 3. 연습 문제

### Lv.1 - 기본

1. `10110₂`를 10진수로 변환하라. (손으로 자리값 전개)
```
1×16 + 0×8 + 1×4 + 1×2 + 0×1 = 16+4+2 = 22
```

2. 10진수 `42`를 2진수와 16진수로 변환하라.
```
2진수 : 42 = 32+8+2 = 101010₂
16진수 : 42 = 2×16 + 10 = 2A₁₆
```

3. 8비트 부호 있는 정수가 표현할 수 있는 최댓값과 최솟값은?
```
최댓값 127 (0111 1111), 최솟값 -128 (1000 0000). 범위는 -2⁷ ~ 2⁷-1
```

### Lv.2 - 응용

1. 8비트 2의 보수로 -20을 표현하라. (3단계 과정 모두 써라)
```
20 = 0001 0100 → 반전 1110 1011 → +1 → 1110 1100 = -20
```

2. 다음 8비트 덧셈을 수행하고, 오버플로 발생 여부를 판단하라: 100 + 50 (둘 다 부호 있는 8비트)
```
100 = 0110 0100, 50 = 0011 0010, 합 = 1001 0110 = -106 (오버플로 발생!). 양수+양수인데 결과 부호비트가 1 → 명백한 오버플로. 올바른 답 150은 8비트 범위(127) 초과.
```

3. SQL에서 INT(32비트) 컬럼에 사용자 수를 저장하다가 글로벌 서비스로 폭증했다. 언제 문제가 생기며, 어떻게 예방하는가?
