# Phase 0 — 오리엔테이션 & CS의 큰 그림

---

> **목표**: 컴퓨터과학(CS)이라는 거대한 지도를 머릿속에 먼저 그린다. 세부 지식을 배우기 전에 "내가 지금 어느 층(layer)을 배우고 있는가"를 항상 위치시킬 수 있게 만드는 것이 이 페이즈의 유일한 미션이다.

---

## 1. 개념 및 정의

### 1-1. 컴퓨터과학이란 무엇인가?

흔한 오해: "컴퓨터과학 = 프로그래밍"
사실 프로그래밍은 CS의 도구이자 일부일 뿐임.

| 정의 관점 | 설명 |
| -------- | ---- | 
| 한 줄 정의 | 계산(computation) - "정보를 어떻게 표현하고, 변환하고, 처리하는가"를 연구하는 학문" |
| 핵심 질문 | ① 무엇을 계산할 수 있는가? ② 얼마나 효율적으로 할 수 있는가? ③ 어떻게 정확하게/안전하게 할 수 있는가? |
| 프로그래밍의 위치 | 위 질문에 대한 답을 기계에게 실행시키는 수단 |

> 비유
> 천문학이 망원경에 관한 학문이 아니듯, CS도 컴퓨터(기계)에 관한 학문이 아니다. - Edsget Dijkstra의 유명한 비유
> CS의 본질은 **계산이라는 추상적 과정**임.

---

### 1-2. 추상화 계층 (Abstraction Layers) - CS의 척추

CS 전체를 관통하는 단 하나의 개념을 꼽으라면 **추상화(Abstraction)**
복잡한 아래층을 숨기고, 위층에는 깔끔한 인터페이스만 노출하는 것.

```
┌───────────────────────────────────────────────────┐
│  애플리케이션  (당신의 Python 앱, Metric Copilot)   │  ← 지금 여기서 일함
├───────────────────────────────────────────────────┤
│  라이브러리/프레임워크 (pandas, FastAPI, LangChain) │
├───────────────────────────────────────────────────┤
│  프로그래밍 언어 (Python, SQL)                      │  ← Phase 6
├───────────────────────────────────────────────────┤
│  운영체제 (Linux, 프로세스/메모리/파일)              │  ← Phase 7
├───────────────────────────────────────────────────┤
│  명령어 집합 / 어셈블리                             │  ← Phase 2
├───────────────────────────────────────────────────┤
│  컴퓨터 구조 (CPU, 메모리, 캐시)                    │  ← Phase 2
├───────────────────────────────────────────────────┤
│  디지털 논리 (게이트, 회로)                         │  ← Phase 1
├───────────────────────────────────────────────────┤
│  데이터 표현 (0과 1, 2진법)                         │  ← Phase 1
└───────────────────────────────────────────────────┘
       ▲ 위로 갈수록 "추상적/편리", 아래로 갈수록 "구체적/실제"
```

이 로드맵은 **맨 아래(0과 1)에서 출발해 위로 올라가는 bottom-up 구조**
현재 나는 개발자로 평소 맨 위 두 층에서 일하므로, 그 아래에 무엇이 깔려 있는지 채우는 여정

---

### 1-3. 핵심 사고 도구 3가지

| 도구 | 의미 | 어디서 쓰이나 | 설명 |
|---|---|---|---|
| **추상화 (Abstraction)** | 불필요한 디테일을 숨기고 본질만 노출 | 함수, 클래스, API, OS 시스템콜 전부 | 내부 구현 가리고 사용에 필요한 최소한의 인터페이스만 남기기 |
| **분해 (Decomposition)** | 큰 문제를 작은 문제로 쪼갬 | 알고리즘 설계, 시스템 디자인 | 거대한 벽을 벽돌 단위로 쪼개어 해결 |
| **패턴 인식 (Pattern Recognition)** | 반복되는 구조를 재사용 | 자료구조 선택, 디자인 패턴 | 과거 해결책을 재사용 |

이 세 가지는 CS뿐 아니라 **PM의 문제 분해, 데이터 분석의 모델링** 정확히 같은 사고 방법
"풀 루프"가 사실 CS의 사고법과 동형(Isomorphic)

```
[복잡하고 거대한 현실의 문제]

1. 분해 (Decomposition) - 문제를 작은 단위 모듈로 쪼개기
2. 패턴 인식 (Pattern Recognization) - 쪼갠 문제에서 익숙한 구조를 찾아 해결책을 매핑
3. 추상화 (Abstraction) - 해결된 로직을 깔끔한 함수나 클래스로 묶어 본질만 남김
```

## 예시

### 예시 1: 추상화 계층을 실감하기 - `print("hello")` 한 줄의 여정

`print("hello")`를 실행하면 아래 계층이 순차적으로 동작함.

```python
print("hello")
```

1. **언어 계층**: Python 인터프리터가 `print` 함수 호출로 해석
2. **라이브러리 계층**: 표준 출력 스트림(`sys.stdout`)에 문자열 전달
3. **OS 계층**: `write()` 시스템 콜 호출 → 커널이 처리 (Phase 7)
4. **문자 인코딩 계층**: "hello" → UTF-8 바이트 `68 65 6C 6C 6F` (Phase 1)
5. **디바이스 계층**: 그 바이트가 터미널 드라이버 → 화면 픽셀로

> 평소엔 1번만 의식하지만, 실제로는 8개 층이 모두 일한다.
> 버그·성능 문제는 보통 "내가 의식하지 못한 아래층"에서 터진다.
> 그래서 아래층을 아는 것이 곧 디버깅력이다.


### 예시 2: "왜 이 지식이 ROI가 높은가?"의 구체적인 장면

| 평소 겪는 현상 | 정체를 아는 Phase |
|---|---|
| `0.1 + 0.2 == 0.30000000000000004` | Phase 1 (부동소수점) |
| 한국어 LLM 토큰이 영어보다 2~3배 비쌈 | Phase 1 (인코딩/토큰화) |
| 같은 쿼리인데 갑자기 느려짐 | Phase 9 (인덱스/옵티마이저) |
| `async`를 붙였는데 안 빨라짐 | Phase 7 (I/O bound vs CPU bound) |
| LLM API 호출이 가끔 타임아웃 | Phase 8 (TCP/HTTP 타임아웃) |

## 3. 연습 문제

### Lv.1 - 기본 (개념 확인)

1. 추상화 계층에서, `pandas`로 CSV를 읽는 코드는 어느 층에 해당하는가? 그 바로 아래 두 층은 무엇인가?
: 라이브러리/프레임워크 계층. 아래는 프로그래밍 언어 계층, 운영체제 계층으로.
운영체제 계층에서 `read()` 시스템 콜이 실행됨.

2. "컴퓨터과학은 컴퓨터에 관한 학문이 아니다"라는 말의 의미를 한 문장으로 설명하라.
: 컴퓨터 과학은 물리적 기계가 아닌 **계산이라는 추상적 과정(정보 표현, 변환, 처리)**이고, 컴퓨터는 그 추상화 과정을 실행하는 도구일 뿐임.

3. 추상화·분해·패턴인식 중, "큰 PM 과제를 마일스톤으로 쪼개는 행위"는 어디에 해당하는가?
: 분해(Decomposition). 동일한 사고가 알고리즘 설계, 시스템 디자인에도 그대로 적용됨.


### Lv.2 — 응용 (계층 추적)

당신은 FastAPI 서버가 클라이언트에게 JSON을 응답함.
이 과정을 추상화 계층 관점에서 위→아래 순서로 최소 4개 층을 들어 설명하라

1. 애플리케이션 계층 : FastAPI 라우터가 Python dict를 반환
2. 라이브러리/프레임워크 계층 : 직렬화기가 dict → JSON 문자열로 변환
3. 프로그래밍 언어 계층 : 문자열을 바이트로 인코딩 (UTF-8)
4. 운영체제 계층 : 소켓에 `send()` 시스템 콜로 바이트 전달 (Phase 7, 8)
5. 네트워크 계층 : TCP 패킷으로 분할되어 전송 (Phase 8)
6. 디지털 논리 계층 : 0과 1의 전기 신호로 물리 매체를 통과
